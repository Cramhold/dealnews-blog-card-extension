# Links tab and the working-copy bridge

The Links tab, the magic URL service, and the `file://` working-copy bridge.

## Links tab and the working-copy bridge (monetized links)

Turns a normal web address into a monetized DealNews link, the same one the CMS plugin makes, without opening the CMS. One shared file, `magic-link.js` (`DNMagic`), does the work and is used from two places: the sidebar's **Links** tab (`initLinks()`, `makeLinks()`, `renderLinks()` in `sidebar.js`) and the service worker (`background.js`). It has no DOM and no `chrome.*` calls; the caller passes the tokens in.

**Flow** (`resolveLink()`): POST the landing URL to `https://url-service.dealnews.net/magic-url/dato-plugin/` with `Authorization: DNADMINAPI <token>` (the scheme word is part of the header) and a body of `{environment: "main", user_email, landing_url, program: {selection: "", options: []}}`. The answer has `vendor` (a DatoCMS record id, numeric or not), `monetized_url`, and `program` (a JSON string with the chosen `selection` and the `options` on offer, each a label and value). The vendor's legacy id comes from DatoCMS (`allVendors(filter: {id: {eq}})` on the CDA with the sidebar's token, falling back to the management API item's `legacy_id`; results are cached for the session). The tag is then `<a href="{monetized_url}" vendor="{legacy_id}" brand="0" category="0" landing_url="{url}" magic_url_info="{label without its (Historical: ...) part} (Default) - {program id}">` and, for a button, `class="btn btn-cta bu-m-0"`. The service picks a default program; when it offers more than one, the Links tab shows a Program menu and asks again with the chosen value (`selection`, with the options echoed back). Nothing here writes to DatoCMS.

**Flags, never guesses.** A result is only usable (`ok`) when there is no `stop` flag. The stops: `bad-url`, `service` (unreachable, an HTTP error, or a redirect to Google sign-in, which means the token was not accepted), `no-vendor`, `no-program` (selection empty: the service found no affiliate program), `no-label`, `no-url`, `same-as-landing` (monetized address equal to the one given; seen for hbomax.com and dealnews.com), `vendor-lookup`. `many-programs` is only a note. Checked against the live service on 2026-11-20 for AliExpress, Target, Walmart, Best Buy, eBay, Amazon, Peacock, Disney+, HBO Max, DealNews and example.org; the AliExpress tag matched the CMS plugin's own output character for character.

**Storage.** The magic URL token and the user's email are in `chrome.storage.local` (`magicToken`, `magicEmail`: this browser only, not synced, never written into any generated output). The DatoCMS token is the existing `datoToken`. The token is an admin-style API credential: do not put it in the repo, a page or a screenshot.

**The working-copy bridge** (`bridge.js`, a content script on `file:///*`): lets the HTML working copies the SEO audit skill builds ask this extension for links, because a page opened from disk cannot call the service itself (the service's CORS allowlist is dealnews.com and dealnews.net subdomains, the CMS admin and the plugin's Vercel origin, so a file page's `null` origin is refused). The script does nothing unless the page has `<meta name="dn-working-copy">`. It forwards two message types only, `MAGIC_RESOLVE` and `MAGIC_STATUS`, to the service worker, which answers them if the sender URL starts with `file://`; the reply holds the link attributes or a flag list, never a token. Page to bridge: `window.postMessage({dnWc: 'req', id, type, url?, selection?}, '*')`; bridge to page: `{dnWc: 'res', id, res}` and `{dnWc: 'ready', version}` (sent once at load and on `type: 'PING'`). Chrome only runs content scripts on local files after **Allow access to file URLs** is switched on for the extension at `chrome://extensions`; without that the page shows how to turn it on and offers a paste-a-tag fallback. Adding `file:///*` and the service host raises new permission prompts, so Chrome may disable the extension until it is accepted again after updating.

**Not verified in a real extension install:** the sidebar tab and `magic-link.js` were run in a test page with the `chrome.*` APIs stubbed and the two network calls forwarded through a local proxy; the service worker, the bridge and the extension's own cross-origin calls were not run inside Chrome.
